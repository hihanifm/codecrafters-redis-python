Queue patterns: RPUSH + LPOP = FIFO job queue (Resque, Sidekiq) · LPUSH + LPOP = stack · LPUSH on a FIFO queue = crude priority lane · LPUSH + LTRIM = capped newest-first feed.

2. Index math (LRANGE)

  • Redis stop is inclusive; Python slice stop is exclusive → stop + 1.
  • Negative index = another name for a position (-1 = last), not a direction.
  • Normalize → translate: len + idx; start still negative → 0; stop still negative → empty; then +1.
  • Fencepost: inclusive count = stop − start + 1; half-open [a, b) count = b − a. Half-open joins cleanly and makes empty ranges natural (Dijkstra).
  • Tested as a pure function with boundary partitions (TDD, table-driven subTest).
Why negatives exist: "last N" = LRANGE k -N -1 in one atomic command. Otherwise LLEN + LRANGE = two round trips and a race between them.

3. Data structure: array vs deque

Python list (dynamic array)dequeRedis list
Push tailO(1) amortizedO(1)O(1)
Push headO(n) (shift all)O(1)O(1)
Index middleO(1)O(n)O(n)
  • Amortized: rare resize copies everything, but geometric growth (CPython ~1/8 + 6) spreads the cost → O(1) average. Single append can still spike.
  • deque = doubly linked blocks of 64 slots. No slicing → itertools.islice (O(stop), like Redis LRANGE O(S+N)).
Tail latency: averages hide spikes; servers care about p99. Redis grows its hash table with incremental rehashing so no single command pays for the whole copy.

4. Store model

store = { b"name": (b"hanif", 0),            # string: value is bytes
          b"jobs": (deque([b"a", b"b"]), 0) } # list: deque of bytes
          key=bytes  (value, deadline)        # value's type = Redis type
  • Keys are binary-safe strings (bytes). : namespacing is convention only.
  • Empty list = no key: pop the last element → delete. Keeps "missing = empty" true, so LLEN 0 / EXISTS 0 stay honest.
  • Nil ($-1) ≠ empty string ($0): "" can be a real element. Absence is not a value. Null array = *-1.

5. Blocking (BLPOP)

  • Python primitives sleep in the kernel: Semaphore (counter) · Event (flag; set() wakes all) · Condition (lock + wait queue; notify() wakes one; re-check in while).
  • Design: per-key deque of waiter slots {"event", "value"} under the global lock. Python = the pager, we keep the clipboard.
  • FIFO fairness: longest waiter served first → no starvation.
  • Hand-off race: waiter wakes, another client LPOPs first. Fix: the pusher pops into the waiter's slot under the lock, then set().
  • Timeout: wait(t); re-take lock; value set → take it, else remove own slot (or a pusher hands a value to a ghost).
Why blocking: polling LPOP every 100 ms = wasted round trips + up to 100 ms latency. Blocking = zero idle traffic, instant wake. Timeout = heartbeat for shutdown and health checks.

6. Code shape

  • Split by layer: main.py (server) · resp.py (protocol) · store.py (data) · commands.py (logic). Mirrors Redis networking.c / t_list.c.
  • Dict dispatch: new command = one function + one line (open/closed).
  • Commands return bytes, never touch sockets → testable. Functional core, imperative shell.
  • Refactor from a green baseline, so a failure points at the refactor.
