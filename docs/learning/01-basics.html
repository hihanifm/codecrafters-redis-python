Redis Ch.1 — Basics

Revision from building Redis in Python · completed 2026-11-25 · 7 stages

1. TCP server

  • socket.create_server(("localhost", 6379)) → accept() blocks until a client connects.
  • recv() returns b"" when the client closes cleanly → close and break, or the loop crashes the server.
  • Abrupt drop raises ConnectionResetError (still unhandled — known gap).

  • Every item sits on its own line ending in \r\n (CR + LF, two bytes). Backslash is escape syntax, not a byte.
  • split(b"\r\n")[2::2] → skip the array header, take every 2nd part → just the values.
  • split drops the delimiter; splitlines(keepends=True), re.split with a group, or partition keep it.
  • Commands are case-insensitive: compare name.upper().

3. Concurrency

  • One thread per client: an idle client blocks only its own thread.
  • GIL: one thread runs Python at a time; released while waiting on I/O → fine for network servers.
  • Single dict operation = safe. Read-modify-write (x = x + 1) = race → needs threading.Lock.
  • GIL safety is a CPython implementation detail, not a language promise. Free-threaded Python (3.13+/3.14) has no GIL.
  • We lock every store access. Keep the critical section tiny; send on the network after releasing.
Why real Redis differs: one thread + an event loop runs every command, so no locks are needed and commands are naturally atomic. Since 6.0, extra threads handle only network I/O.

4. Consistency terms

  • Eventual consistency = distributed replicas may serve stale data for a while. Not our case.
  • Lock-free single reads here are still consistent. Torn reads appear when one write touches several keys.

5. Expiry (SET … PX ms)

  • Store (value, deadline); deadline = now + px, 0 = none. PX 0 → error.
  • Lazy expiration: check on GET, delete if past deadline. Check + delete = one lock.
  • Terms: elapsed = time spent · TTL = time to live · deadline = when it dies.
  • time.monotonic() never jumps backwards → safe for durations. time.time() is wall clock and can jump.
Why Redis does both lazy + active: lazy is cheap per read, but keys nobody reads again leak memory. Redis also samples keys periodically to evict them. Redis stores wall-clock ms because deadlines are persisted to disk.

6. Python bits picked up

  • Tuples: record = (value, deadline) packs, value, deadline = record unpacks. The comma makes the tuple.
  • Slicing [start:stop:step]; a, b = b, a swaps.

7. Tangents worth keeping

  • Redis: written in C by antirez (2009). 2.6 Lua · 3.0 Cluster · 4.0 Modules · 5.0 Streams · 6.0 ACL/TLS/RESP3 · 2024 license change → Valkey fork · 8.0 AGPL option back.
  • ACLs = identity + allowed actions + allowed resources, deny the rest. Same idea scales to agents: per-group identities, read vs act credentials, human confirm for side effects.
  • Frontend vs backend: different domains, not ranked — MVC/MVP were born in UI work.
